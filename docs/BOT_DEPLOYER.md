# MAXIMUS TWP Telegram Deployer — operator guide

[Repository](../README.md) · [راهنمای فارسی](QUICKSTART.fa.md)

The optional deployer is designed for a Telegram assistant that prepares a per-user Cloudflare Worker deployment. Its default user-facing language is **English**; users can switch to **Persian** from the bot menu and in the form.

## Before setup

1. Create your own bot in [@BotFather](https://t.me/BotFather) using `/newbot`. Save the bot token privately.
2. Create or choose a Cloudflare account in which to host the **deployer Worker** (separate from each user’s target account).
3. Send `/id` to your bot to retrieve your own numeric Telegram user ID, then configure a private owner allowlist (`BOT_OWNER_IDS`) for the first release. Do **not** publish the deployer as an unrestricted service without abuse controls.
4. The generated Worker contains the current MAXIMUS TWP core bundled during `npm run build:deployer`. This is a separate Cloudflare Worker from the one running the bot.

## Deploy the bot

```bash
npm install
npm run check
npm run build:deployer
npx wrangler login
npx wrangler secret put TELEGRAM_BOT_TOKEN --config deployer/wrangler.toml
npx wrangler secret put TELEGRAM_WEBHOOK_SECRET --config deployer/wrangler.toml
npx wrangler secret put SETUP_SIGNING_KEY --config deployer/wrangler.toml
npx wrangler secret put BOT_OWNER_IDS --config deployer/wrangler.toml
npm run deploy:deployer
```

- `TELEGRAM_BOT_TOKEN`: token generated by BotFather.
- `TELEGRAM_WEBHOOK_SECRET`: 32 or more random alphanumeric characters (allowed characters: A-Z, a-z, 0-9, `_`, `-`).
- `SETUP_SIGNING_KEY`: a separate 64-character random hexadecimal value; used to sign time-limited setup links.
- `BOT_OWNER_IDS`: your numeric Telegram account ID(s), comma-separated. The deployer refuses unauthorized users by default.

**Use a separate secret for every variable.** None belongs in the repository, chat history or public logs.

## Register the Telegram webhook

After deploying, note your deployer Worker URL. Run:

```bash
node scripts/register-telegram-webhook.mjs https://YOUR-DEPLOYER.workers.dev/telegram
```

The script reads `TELEGRAM_BOT_TOKEN` and `TELEGRAM_WEBHOOK_SECRET` from **environment variables** in your trusted local terminal. These values must match the Cloudflare secrets. Alternatively, configure `setWebhook` manually using Telegram’s Bot API. Do not paste tokens into third-party websites or commit shell history with credentials.

Send `/start` to [@drfxtwp_bot](https://t.me/drfxtwp_bot) after installing its **rotated** bot token. The menu offers **Deploy TWP**, **Installation guide**, **Language / زبان**, and **Security**. The bot issues a **10-minute signed HTTPS setup link**.

## End-user deployment

1. Select **Deploy TWP** in the bot.
2. Open the setup page, ideally in an external trusted browser.
3. In Cloudflare, create an API token restricted to **Workers Scripts: Edit** for one account (prefer short expiry). Do not enable KV or All Accounts by default.
4. Enter Cloudflare account ID, account `workers.dev` subdomain, desired Worker name and the scoped API token in the secure form.
5. On success, copy the one-time `ADMIN_TOKEN` and private proxy link. Test Telegram connectivity with a WEB-proxy-capable client.
6. Revoke the temporary Cloudflare API token when installation is complete.

The browser sends the Cloudflare token directly to the deployer Worker via HTTPS **once**, for Worker provisioning; it is not sent to Telegram. No KV, D1, or database stores the token. A privileged deployer still handles the token in memory. Admin credentials appear only in the resulting browser page.

## Release safety & limitations

- The deployer is shipped as source and a build flow; it is **not** automatically deployed just by pushing to GitHub.
- One-click deployment requires real Cloudflare API integration testing on a controlled test account. A successful API response is not a proof of Telegram transport availability.
- The deployer **does not deploy VLESS, EdgeTunnel, X-UI, or arbitrary scripts**. Only the bundled MAXIMUS TWP Worker is allowed.
- Each user must control their own Cloudflare account and token; do not operate with Global API Keys or silently reuse an administrator's account.

## Credential safety for @drfxtwp_bot

The bot identifier is `@drfxtwp_bot`. **Its previously shared bot token must be revoked in [@BotFather](https://t.me/BotFather) and replaced** before configuring a live webhook. If a user accidentally sends a token-like message to this bot, the bot tries to delete it immediately and warns the user to rotate the credential. Telegram may already have processed the original message, so deletion is not a substitute for rotation.
